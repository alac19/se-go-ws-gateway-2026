## 一、测试概述

### 1.1 测试目标

验证 WebSocket 网关在功能、可靠性、性能方面满足需求规格说明书的要求，确保以下核心能力：

- WebSocket 连接建立、注册、注销与心跳保活
- 全服广播、房间广播、单播三种消息推送模式
- 连接管理器与房间管理器的并发安全性
- 优雅启停（信号捕获 + 宽限期 + 资源清理）
- HTTP REST API 的正确性与健壮性
- 限流防护与请求校验
- Prometheus 监控指标暴露
- 结构化日志输出
- 配置管理（config.toml + 环境变量覆盖）

### 1.2 测试范围

| 测试类型 | 覆盖范围 |
| -------- | -------- |
| 单元测试 | 连接管理器、房间管理器、消息路由、限流器、配置加载、工具函数 |
| 集成测试 | 端到端功能测试（WebSocket 连接、消息推送、HTTP API） |
| 性能测试 | 连接建立、广播吞吐量、混合负载下的延迟和资源占用 |
| 安全性测试 | 限流、请求校验、特殊字符过滤、重复 clientId 拒绝 |

## 三、测试策略

### 3.1 测试方法

- **单元测试**：使用 Go 标准 `testing` 包，运行 `go test -v -cover ./...` 获取覆盖率和结果。
- **集成测试**：通过手工执行 `curl` 和浏览器控制台/wstool 验证完整业务流程（连接建立、注册/注销、心跳、广播/单播/房间广播、统计、限流、优雅退出）。
- **性能测试**：使用 `hey` 对 HTTP API 进行压测；使用 `wscat` 或 Python 脚本模拟多客户端 WebSocket 连接，验证连接数上限和消息延迟。
- **安全性测试**：验证限流返回 429、特殊字符校验返回 400/关闭帧、重复 clientId 拒绝。

### 3.2 测试通过标准

- **单元测试**：所有测试用例通过，核心模块代码覆盖率 ≥ 80%。
- **集成测试**：所有功能需求验证通过，无功能性缺陷。
- **性能测试**：并发连接数 ≥ 2,000，P99 延迟 < 50ms。
- **安全性测试**：限流正确拦截超频请求；特殊字符和重复 clientId 被正确拒绝。

## 四、测试用例

### 4.1 单元测试用例

| 模块 | 测试内容 | 验证点 | 覆盖率目标 |
| ---- | -------- | ------ | ---------- |
| `pkg/logger` | 日志级别解析、文件创建、默认输出 | 初始化无 panic，文件可写 | 90% |
| `pkg/limiter` | Allow 方法、多 IP 独立、令牌恢复、并发安全 | 限流逻辑正确，并发安全 | 100% |
| `internal/middleware/ratelimit` | 限流中间件（Allow 返回 true/false 时的行为） | 返回 429 或正常放行 | 100% |
| `internal/config` | LoadConfig、ApplyEnvOverrides、Validate | 配置加载正确，校验生效，环境变量覆盖 | 90% |
| `service/client_manager` | Register/Unregister/Get/Range/GetOnlineCount/Init/Shutdown | 连接池操作正确，并发安全，指标更新正确 | 80% |
| `service/room_manager` | Join/Leave/GetClients/RemoveClientFromAllRooms/GetAllRoomsConnStats/HasRoom | 房间成员管理正确，读写锁安全 | 85% |
| `service/message_router` | SendSingle/SendRoom/SendBroadcast（含目标在线/离线/通道满场景） | 消息路由正确，非阻塞发送，指标正确 | 80%* |

> *`message_router.go` 中的 Redis Pub/Sub 扩展相关代码（`subscribeRedis` 等），该功能为可选扩展，当前版本未启用，不纳入单元测试要求。`client_manager.go` 未覆盖部分为 conn 相关分支和防御性分支，属于边界情况，已在集成测试中覆盖。而 handler 层因涉及 WebSocket 协议升级和协程管理，也交由集成测试覆盖，不重复编写单元测试。

### 4.2 集成测试用例

> 以下用例通过 `curl`（HTTP API）和浏览器控制台/wstool（WebSocket）执行，验证系统整体功能。在服务启动后依次测试，并记录结果。

| 编号 | 测试项 | 操作步骤 | 预期结果 |
| ---- | ------ | -------- | -------- |
| **WebSocket 连接与心跳** | | | |
| IT01 | WebSocket 连接建立 | wstool 连接 `ws://localhost:8080/ws?clientId=test&roomId=room1` | 连接成功，服务端输出 `注册成功` |
| IT02 | 心跳保活 | 连接后等待 30 秒，观察服务端日志 | Ping/Pong 成对出现，`LastPong` 更新 |
| IT03 | 参数缺失拒绝 | 浏览器控制台执行：`new WebSocket("ws://localhost:8080/ws?clientId=test&roomId=")`，监听 `onclose` 事件查看状态码 | 连接关闭，状态码 4000，关闭原因 `clientId and roomId are required` |
| IT04 | 特殊字符拒绝 | 浏览器控制台执行：`new WebSocket("ws://localhost:8080/ws?clientId=test.&roomId=room1")`，监听 `onclose` 事件查看状态码 | 连接关闭，状态码 4001，关闭原因 `invalid clientId format` 或 `invalid roomID format` |
| IT05 | 重复 clientId 拒绝 | 先连接 `test1`，再连接相同 `clientId` | 第二次连接关闭，状态码 4002 |
| **消息路由** | | | |
| IT06 | 全服广播 | `curl -X POST http://localhost:8080/api/broadcast -H "Content-Type: application/json" -d '{"type":"text","data":"hello"}'` | 返回 200，所有在线客户端收到消息 |
| IT07 | 房间广播 | `curl -X POST "http://localhost:8080/api/room/room1/broadcast" -H "Content-Type: application/json" -d '{"type":"text","data":"hello"}'` | 返回 200，room1 客户端收到，room2 客户端收不到 |
| IT08 | 房间不存在 | `curl -X POST "http://localhost:8080/api/room/nonexistent/broadcast" -H "Content-Type: application/json" -d '{"type":"text","data":"hello"}'` | 返回 404 `目标房间不存在` |
| IT09 | 单播（在线） | `curl -X POST http://localhost:8080/api/client/test/send -H "Content-Type: application/json" -d '{"type":"text","data":"hello"}'` | 返回 200，指定客户端收到消息 |
| IT10 | 单播（离线） | `curl -X POST http://localhost:8080/api/client/offline/send -H "Content-Type: application/json" -d '{"type":"text","data":"hello"}'` | 返回 404 `目标客户端离线或不存在` |

### 4.3 性能测试用例

> 预期目标：并发连接数 ≥ 2,000，P99 延迟 < 50ms（视实际硬件条件记录实测值，作为后续优化基准）

| 编号 | 测试场景 | 测试方法 | 记录指标 |
| ---- | -------- | -------- | -------- |
| PT01 | 连接建立性能 | 使用 Python 脚本或 wscat 模拟 1,000 个客户端同时建立连接 | 连接建立时间、资源占用（内存/CPU） |
| PT02 | 广播压力测试 | 建立 1,000 个连接后，通过 HTTP 接口触发广播消息 | P50/P95/P99 延迟、消息送达率 |
| PT03 | 混合负载 | 广播同时，部分客户端发送上行消息 | 吞吐量、延迟分布、错误率 |
| PT04 | 长时间稳定性 | 保持 1,000 连接运行 30 分钟，每 30 秒触发一次广播 | 内存增长趋势、连接稳定性 |

> **说明**：在现有硬件条件下，验证网关在高并发场景下的稳定性，记录实际可达到的并发连接数和 P99 延迟分布。重点验证架构在现有环境下的表现和调优能力。PT01-PT03 为必测项，PT04 为选测项。

### 4.4 安全性测试用例

| 编号 | 测试项 | 操作步骤 | 预期结果 |
| ---- | ------ | -------- | -------- |
| ST01 | 限流防刷 | 同 IT16，快速发送超过阈值的请求 | 返回 429 |
| ST02 | clientId 特殊字符 | 使用 `clientId=test.` 连接 | 连接关闭，状态码 4001 |
| ST03 | roomId 特殊字符 | 使用 `roomId=room!` 连接 | 连接关闭，状态码 4001 |
| ST04 | 重复 clientId 并发 | 使用脚本同时发起多个相同 clientId 的连接 | 仅 1 个成功，其余被拒绝（状态码 4002） |

## 五、测试执行计划

1. **单元测试执行**：运行 `go test -v -cover ./...`，记录每个包的通过情况和覆盖率，截图保存。
2. **集成测试执行**：按照 IT01~IT21 顺序执行，使用 `curl` 和 wstool/浏览器控制台，保存输出日志或截图。
3. **性能测试执行**：
   - 启动服务（`go run cmd/gateway/main.go`）。
   - 使用 Python 脚本或 wscat 模拟多客户端连接。
   - 执行 PT01~PT03，记录 QPS、延迟、资源占用。
4. **安全性测试执行**：按照 ST01~ST04 顺序执行，验证防护是否生效。
5. **测试报告编写**：汇总所有结果，形成最终报告。
