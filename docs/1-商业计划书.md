# 轻量级 WebSocket 实时推送网关商业计划书

## 一、项目概述
### 1.1 项目名称
轻量级 WebSocket 实时推送网关

### 1.2 项目性质
本项目属于后端中间件 / 基础设施，面向企业研发团队提供标准化长连接治理能力，统一承接 WebSocket 流量、提供 REST 消息推送能力。旨在解决业务自研长连接重复开发、性能差、无监控、启停丢消息等痛点，属于支撑实时业务的底层技术底座，非 C 端应用软件。同时本项目为团队实训开发项目，完整产出源码、可视化前端控制台、全套技术文档与答辩材料。

### 1.3 开发目标
基于 Go 高并发特性，搭建开箱即用的 WebSocket 网关，配套开发简易前端控制台用于调试、查看在线连接与房间状态。核心指标：单机 5000 + 并发长连接、消息 P99 延迟≤50ms。内置心跳保活、房间分组、优雅启停、Prometheus 监控；默认纯内存零依赖运行，支持 Redis 扩展分布式部署，有效降低实时业务开发与运维成本。

### 1.4 开发周期
总周期**28天**，六人并行协作开发。
1‑5天：技术调研、方案论证、环境搭建、项目初始化、架构设计评审、接口契约定义；
6‑18天：后端核心模块、Redis分布式扩展、前端控制台并行编码开发；
19‑24天：单元测试、集成测试、压力测试、性能调优、前后端完整联调；
25‑27天：全量回归BUG修复、全套文档撰写完善、答辩素材制作；
28天：项目整体验收、预答辩演练、成果打包交付。

## 二、行业与市场分析
### 2.1 行业背景
直播、在线教育、IoT、金融行情、多人协作等场景对 WebSocket 实时推送需求激增。目前行业存在两大问题：中小企业业务自研长连接逻辑，重复开发、性能弱、稳定性差；主流开源中间件臃肿、依赖多、Go 适配差、部署成本高，不适合轻量业务。因此轻量化 Go 版 WebSocket 网关具备明确市场需求。同时配套可视化控制台可以降低运维调试门槛，进一步提升产品易用性。

### 2.2 目标用户
中小互联网研发团队：需要快速落地实时业务，规避底层重复开发；
高校实训与开源开发者：用于 Go 高并发网络编程学习与二次开发；
运维人员：需要可视化面板观测长连接状态、调试推送消息。

### 2.3 市场痛点
自研开发成本高、代码冗余；单机并发能力弱、消息延迟波动大；缺少监控日志，运维排障困难；无优雅启停，重启易丢消息；传统中间件依赖多、部署门槛高；缺少简易可视化调试面板，排查问题只能调用接口查看原始指标，使用门槛较高。

## 三、产品定位与核心优势
### 3.1 产品定位
定位为微服务轻量化实时推送中间件，主打零依赖、高性能、易部署、可扩展，配套简易前端可视化控制台，填补 Go 生态轻量 WebSocket 网关空白，适配中小企业实时业务与技术实训场景。

### 3.2 核心优势
轻量低耗：纯 Go 实现、无重型依赖，单连接内存占用≤10KB，资源消耗极低。
高性能高并发：协程 + 通道模型，单机 5000 + 并发连接，P99 延迟≤50ms，隔离慢连接保障全局稳定。
开箱即用：极简配置，标准化 REST 推送接口，配套可视化调试前端，业务零改造快速接入。
可观测运维：内置 Prometheus 监控、结构化日志、健康检查接口，前端面板直观展示连接、房间、消息统计。
稳定可靠：心跳保活、僵尸连接清理、优雅启停，杜绝消息丢失。
灵活扩展：模块化架构，支持单机内存模式与 Redis 集群分布式部署。

## 四、项目功能与预期成果
### 4.1 核心功能
WebSocket 连接全生命周期管理、30s 心跳检测、异常连接自动清理；
标准化 REST 接口：广播、房间组播、点对点推送、在线状态查询；
高性能异步消息路由，隔离慢客户端，避免全局阻塞；
系统信号监听、优雅启停，保障停机消息不丢失；
监控日志、健康检测、纯内存 / Redis 双模式、Docker 容器化部署；
前端控制台功能：在线连接查看、房间管理、模拟消息推送、指标可视化展示。

### 4.2 交付成果
规范完整 Go 后端源码、前端控制台源码、架构与接口文档、测试用例与压测脚本、性能测试报告、部署手册、答辩 PPT 与讲稿、全套项目结题文档。

## 八、风险分析与应对
性能不达标风险：优化异步分发、缓冲区参数，隔离慢连接、减少锁竞争，持续压测调优后端逻辑，预留充足压测调优周期。
并发安全风险：采用 sync.Map、读写锁，统一资源回收逻辑，单元测试充分覆盖并发场景。
消息丢失风险：实现信号监听 + 优雅关停，预留消息推送宽限期，平滑释放资源。
前后端联调风险：提前约定接口字段，前后端分开 Mock 调试，预留充足联调缓冲时间。
开发延期风险：每日进度同步，模块解耦并行开发；答辩材料分散穿插制作，不集中堆到末期；出现阻塞及时调整任务分工。
磁盘环境风险：统一将 Go 环境、前端项目目录配置至 D 盘，避免 C 盘缓存溢出影响开发。
答辩演示风险：林海亮提前组织多轮预演，准备备用演示方案，规避现场环境异常。
