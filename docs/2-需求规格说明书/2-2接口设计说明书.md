## 一、引言

### 1.1 文档目的

本文档定义 WebSocket 实时推送网关对外提供的 WebSocket 接入接口、HTTP REST API、健康检查与监控指标接口，包括请求方法、路径、参数、响应格式及错误码，供前端客户端或业务后端调用方参考。

### 1.2 适用范围

本文档适用于网关服务的开发、测试及对接阶段。REST API 响应数据格式为 JSON，WebSocket 消息格式为文本帧（TextMessage）。文档中的接口定义与最终实现保持一致，涵盖心跳保活、限流防护、优雅退出等已交付能力。

### 1.3 接口一览

| 序号 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 1 | GET | `/ws` | WebSocket 长连接接入 |
| 2 | POST | `/api/broadcast` | 全服广播 |
| 3 | POST | `/api/room/:roomId/broadcast` | 房间广播 |
| 4 | POST | `/api/client/:clientId/send` | 单播推送 |
| 5 | GET | `/api/stats` | 连接统计 |
| 6 | GET | `/health` | 健康检查 |
| 7 | GET | `/metrics` | Prometheus 监控指标 |

> 说明：`/api` 路由组统一挂载基于客户端 IP 的令牌桶限流中间件，默认令牌生成间隔 12 秒、桶容量 5。

## 二、外部接口

### 2.1 WebSocket 接入

**接口描述**：客户端通过 WebSocket 协议连接到网关，建立全双工长连接。连接建立后自动注册到全局连接池，并按 `roomId` 加入对应房间；服务端定期发送 Ping 帧进行心跳保活，并支持向客户端推送下行消息。

- **请求方法**：`GET`
- **请求路径**：`/ws`
- **请求参数**：

  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | `clientId` | string | 是 | 客户端唯一标识，由调用方生成并传入，仅允许字母、数字、下划线、短横线 |
  | `roomId` | string | 是 | 房间 ID，标识客户端所属分组，格式要求同 `clientId` |

- **参数格式**：`^[a-zA-Z0-9_-]+$`，长度至少为 1
- **协议升级**：HTTP → WebSocket（状态码 `101 Switching Protocols`）

**连接成功**：
- 协议升级成功，进入 WebSocket 全双工通信模式
- 客户端自动注册，并加入 `roomId` 对应的房间
- 服务端每 30 秒（可配置）发送一次 Ping 帧；客户端须在 60 秒（可配置）内回复 Pong 帧
- 若 `clientId` 已存在，新连接会被拒绝并收到关闭帧（状态码 4002）

**连接失败 / 被拒绝**：

| 场景 | 客户端收到的关闭码 | 说明 |
|------|--------------------|------|
| `clientId` 或 `roomId` 缺失 | `4000` | 参数缺失 |
| `clientId` 或 `roomId` 含非法字符 | `4001` | 参数格式无效 |
| `clientId` 已被占用 | `4002` | 重复连接被拒绝 |
| 网关正在优雅退出 | `1001` | 服务正在关闭，拒绝新连接 |
| 正常关闭 / 服务优雅关闭现有连接 | `1000` | 正常关闭 |

**协议升级失败（HTTP 错误）**：
- `500 Internal Server Error`：WebSocket 协议升级失败（例如请求头缺少 Upgrade 字段）
  ```json
  {"code":500,"status":"error","error":"WebSocket 协议升级失败"}
  ```

**JavaScript 接入示例**：
```javascript
const ws = new WebSocket("ws://localhost:8080/ws?clientId=test001&roomId=room1");
ws.onopen = () => console.log("连接已建立");
ws.onmessage = (e) => console.log("收到消息:", e.data);
ws.onclose = (e) => console.log("连接已关闭，状态码:", e.code);
```

### 2.2 全服广播

**接口描述**：向当前网关所有在线 WebSocket 客户端广播消息。业务后端通过此接口推送全局通知、系统公告等。

- **请求方法**：`POST`
- **请求路径**：`/api/broadcast`
- **请求头**：`Content-Type: application/json`
- **请求体**：合法的 JSON 对象或 JSON 数组，网关只校验 JSON 合法性，消息内容原样转发
  ```json
  {
    "type": "text",
    "data": "这是一条全服广播消息",
    "timestamp": 1770451200000
  }
  ```

- **响应成功（200 OK）**：
  ```json
  {"code":0,"status":"success","data":null}
  ```

- **错误响应**：

  | 状态码 | 响应体示例 | 触发场景 |
  |--------|------------|----------|
  | `400` | `{"code":400,"status":"error","error":"请求体不能为空"}` | 请求体为空 |
  | `400` | `{"code":400,"status":"error","error":"无效的 JSON 格式"}` | 非 JSON 或纯数字请求体 |
  | `429` | `{"error":"too many requests"}` | 触发 IP 限流 |

### 2.3 房间广播

**接口描述**：向指定房间内所有在线客户端广播消息。适用于直播弹幕、在线课堂、游戏对局等按房间隔离的场景。

- **请求方法**：`POST`
- **请求路径**：`/api/room/:roomId/broadcast`
- **请求头**：`Content-Type: application/json`
- **路径参数**：

  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | `roomId` | string | 是 | 目标房间 ID，非空；房间无人时自动回收，广播前需存在 |

- **请求体**：合法的 JSON 对象或 JSON 数组，网关只校验 JSON 合法性，消息内容原样转发
  ```json
  {
    "type": "text",
    "data": "这是一条房间内广播消息",
    "timestamp": 1770451200000
  }
  ```

- **响应成功（200 OK）**：
  ```json
  {"code":0,"status":"success","data":null}
  ```

- **错误响应**：

  | 状态码 | 响应体示例 | 触发场景 |
  |--------|------------|----------|
  | `400` | `{"code":400,"status":"error","error":"请求体不能为空"}` | 请求体为空 |
  | `400` | `{"code":400,"status":"error","error":"无效的 JSON 格式"}` | 非 JSON 或纯数字请求体 |
  | `404` | `{"code":404,"status":"error","error":"目标房间不存在"}` | 房间不存在或无在线成员 |
  | `429` | `{"error":"too many requests"}` | 触发 IP 限流 |

### 2.4 单播推送

**接口描述**：向指定的单个客户端发送消息。适用于点对点通知，如私信提醒、任务状态变更等。

- **请求方法**：`POST`
- **请求路径**：`/api/client/:clientId/send`
- **请求头**：`Content-Type: application/json`
- **路径参数**：

  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | `clientId` | string | 是 | 目标客户端唯一标识，非空 |

- **请求体**：合法的 JSON 对象或 JSON 数组，网关只校验 JSON 合法性，消息内容原样转发
  ```json
  {
    "type": "text",
    "data": "这是一条私信消息",
    "timestamp": 1770451200000
  }
  ```

- **响应成功（200 OK）**：
  ```json
  {"code":0,"status":"success","data":null}
  ```

- **错误响应**：

  | 状态码 | 响应体示例 | 触发场景 |
  |--------|------------|----------|
  | `400` | `{"code":400,"status":"error","error":"请求体不能为空"}` | 请求体为空 |
  | `400` | `{"code":400,"status":"error","error":"无效的 JSON 格式"}` | 非 JSON 或纯数字请求体 |
  | `404` | `{"code":404,"status":"error","error":"目标客户端离线或不存在"}` | 客户端离线、不存在或发送通道已满被判定为慢客户端 |
  | `429` | `{"error":"too many requests"}` | 触发 IP 限流 |

### 2.5 连接统计

**接口描述**：查询当前网关的在线连接统计信息，包括总在线连接数、各房间连接分布和服务运行时长，用于监控网关健康状态。

- **请求方法**：`GET`
- **请求路径**：`/api/stats`
- **请求参数**：无
- **响应成功（200 OK）**：

  ```json
  {
    "code": 0,
    "status": "success",
    "data": {
      "online_connections": 3,
      "all_rooms_connections_stats": {
        "room1": 2,
        "room2": 1
      },
      "gateway_server_initial_time": 3600
    }
  }
  ```

- **响应字段说明**：

  | 字段 | 类型 | 说明 |
  |------|------|------|
  | `online_connections` | int | 当前在线连接总数 |
  | `all_rooms_connections_stats` | object | 各房间在线连接数，key 为 `roomId` |
  | `gateway_server_initial_time` | int | 服务启动至今的运行时长（秒） |

- **错误响应**：`429`，响应体为 `{"error":"too many requests"}`

### 2.6 健康检查

**接口描述**：用于容器编排、负载均衡和运维监控探活。

- **请求方法**：`GET`
- **请求路径**：`/health`
- **请求参数**：无
- **响应成功（200 OK）**：

  ```json
  {"status":"ok"}
  ```

- **说明**：`/health` 不在 `/api` 路由组下，不参与限流，服务存活时始终返回 200。

### 2.7 Prometheus 监控指标

**接口描述**：以 Prometheus 文本格式暴露监控指标，供 Prometheus 或运维监控系统采集。

- **请求方法**：`GET`
- **请求路径**：`/metrics`
- **请求参数**：无
- **响应成功（200 OK）**：`Content-Type: text/plain; version=0.0.4`
- **暴露指标**：

  | 指标名 | 类型 | 标签 | 说明 |
  |--------|------|------|------|
  | `ws_active_connections` | Gauge | 无 | 当前在线 WebSocket 长连接数 |
  | `ws_gateway_msg_sent_total` | Counter | `msg_type`（single/room/broadcast） | 消息发送总次数 |
  | `ws_gateway_msg_send_fail_total` | Counter | `reason`（single_offline/single_block/broadcast_block） | 消息发送失败次数 |
  | `ws_connection_events_total` | Counter | 无 | 连接建立/关闭事件总数 |
  | `ws_messages_received_total` | Counter | 无 | 客户端上行消息接收总数 |

- **说明**：`/metrics` 不在 `/api` 路由组下，不参与限流。生产环境建议通过防火墙或网络策略限制访问范围。

## 三、WebSocket 通信协议

### 3.1 连接生命周期

```
客户端                          网关
  |                              |
  |-- GET /ws?clientId&roomId -->|
  |<-- 101 Switching Protocols --|
  |                              |
  |<-- (服务端推送消息) -----------|
  |-- (上行消息，仅维持活跃) -->|
  |<-- Ping (默认每30s) ----------|
  |-- Pong (默认60s内回复) ------>|
  |                              |
  |-- (连接关闭/心跳超时) ------>|
  |<-- 关闭帧 1000 --------------|
  |-- 注销，离开房间 ------------>|
  |                              |
  |-- (服务优雅退出时) ---------->|
  |<-- 关闭帧 1000 / 新连接1001 -|
```

### 3.2 消息格式

- **下行消息**（服务端 → 客户端）：服务端以 WebSocket TextMessage 帧推送 UTF-8 编码的 JSON 字符串。网关不解析、不修改消息字段，推送内容为调用方提交的原始请求体。示例：

  ```json
  {
    "type": "text",
    "data": "消息内容",
    "timestamp": 1770451200000
  }
  ```

- **上行消息**（客户端 → 服务端）：当前版本不对上行消息做业务处理，仅通过读取消息维持连接活跃，并累计到 `ws_messages_received_total` 指标。网关不要求上行消息格式。

### 3.3 心跳保活

- 服务端以可配置间隔（默认 30 秒）发送 Ping 帧
- 客户端须在可配置超时时间（默认 60 秒）内回复 Pong 帧
- 每次收到 Pong 后，服务端延长该连接的读超时
- 超时未响应则服务端主动关闭连接，并触发注销流程

| 参数 | 默认值 | 配置项 | 环境变量 |
|------|--------|--------|----------|
| Ping 发送间隔 | 30s | `heartbeat.ping_interval_seconds` | `WS_PING_INTERVAL` |
| Pong 等待超时 | 60s | `heartbeat.pong_wait_seconds` | `WS_PONG_WAIT` |
| Ping 帧写入超时 | 10s | `heartbeat.ping_write_timeout_seconds` | - |
| 读超时 | 60s | `websocket.read_deadline_seconds` | - |
| 写超时 | 10s | `websocket.write_deadline_seconds` | - |
| 控制帧写入超时 | 1s | `websocket.control_write_timeout_seconds` | - |

### 3.4 WebSocket 关闭码

| 关闭码 | 含义 | 触发场景 |
|--------|------|----------|
| `1000` | 正常关闭 | 客户端主动关闭、连接异常断开后的清理、服务优雅关闭现有连接 |
| `1001` | 服务正在关闭 | 优雅退出期间拒绝新连接 |
| `4000` | 参数缺失 | `clientId` 或 `roomId` 为空 |
| `4001` | 参数格式无效 | `clientId` 或 `roomId` 包含非法字符 |
| `4002` | clientId 已存在 | 重复连接被拒绝 |

## 四、错误码说明

### 4.1 HTTP 状态码

| HTTP 状态码 | 业务含义 | 说明 |
|-------------|----------|------|
| `200 OK` | 请求成功 | 正常返回业务数据 |
| `400 Bad Request` | 请求参数错误 | 请求体为空、非 JSON、纯数字等 |
| `404 Not Found` | 资源不存在 | 房间不存在或无在线成员、客户端离线或不存在 |
| `429 Too Many Requests` | 触发限流 | 请求频率超过令牌桶阈值 |
| `500 Internal Server Error` | 服务内部错误 | 当前主要用于 WebSocket 协议升级失败等场景 |

### 4.2 业务响应码

| 业务码 | 含义 | 说明 |
|--------|------|------|
| `0` | 成功 | 所有正常响应 |
| `400` | 请求参数错误 | JSON 格式无效、请求体为空等 |
| `404` | 资源不存在 | 目标房间或目标客户端不存在 |
| `500` | 服务器内部错误 | WebSocket 协议升级失败等 |

### 4.3 限流说明

- 作用范围：`/api` 路由组下的全部 REST 接口
- 算法：基于客户端 IP 的令牌桶（`golang.org/x/time/rate`）
- 默认参数：令牌生成间隔 12 秒，桶容量 5，即同一 IP 连续第 6 次请求返回 429
- 配置方式：`configs/config.toml` 的 `[ratelimit]` 段，或环境变量 `WS_RATELIMIT_INTERVAL`、`WS_BURST`
- 响应格式：触发限流时返回 `{"error":"too many requests"}`，与普通业务响应的 `code/status/data` 格式不同，调用方需单独处理
