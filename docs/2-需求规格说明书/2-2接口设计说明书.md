## 一、引言

### 1.1 文档目的

本文档定义 WebSocket 实时推送网关对外提供的 WebSocket 接入接口、HTTP REST API、健康检查与监控指标接口，包括请求方法、路径、参数、响应格式及错误码，供前端客户端或业务后端调用方参考。

### 1.2 适用范围

本文档适用于网关服务的开发、测试及对接阶段。REST API 响应数据格式为 JSON，WebSocket 消息格式为文本帧（TextMessage）。文档中的接口定义与最终实现保持一致，涵盖心跳保活、限流防护、优雅退出等已交付能力。

自 v1.2 起网关引入 JWT 鉴权：管理员先调用登录接口换取令牌，之后访问受保护接口需携带令牌，WebSocket 接入同样需要携带令牌并与客户端标识绑定。仅登录、健康检查与监控指标接口可匿名访问。

### 1.3 接口一览

| 序号 | 方法 | 路径 | 说明 | 是否需要令牌 |
|------|------|------|------|--------------|
| 1 | POST | `/api/auth/login` | 管理员登录，换取 JWT 令牌 | 否 |
| 2 | GET | `/ws` | WebSocket 长连接接入 | 是（query 参数 `token`） |
| 3 | POST | `/api/broadcast` | 全服广播 | 是 |
| 4 | POST | `/api/room/:roomId/broadcast` | 房间广播 | 是 |
| 5 | POST | `/api/client/:clientId/send` | 单播推送 | 是 |
| 6 | GET | `/api/stats` | 连接统计 | 是 |
| 7 | GET | `/health` | 健康检查 | 否 |
| 8 | GET | `/metrics` | Prometheus 监控指标 | 否 |

> 说明：`/api` 路由组统一挂载基于客户端 IP 的令牌桶限流中间件（默认令牌生成间隔 12 秒、桶容量 5）与 JWT 鉴权中间件；登录接口仅受限流保护，健康检查与监控指标不在 `/api` 组内。令牌的传递方式与校验规则见第四章「鉴权机制」。

## 二、外部接口

### 2.1 管理员登录

**接口描述**：管理员使用账号与口令登录，成功后返回 JWT 令牌，后续访问受保护接口与建立 WebSocket 连接均需携带该令牌。当前版本使用配置文件中预置的管理员账号，不依赖外部数据库。

- **请求方法**：`POST`
- **请求路径**：`/api/auth/login`
- **请求头**：`Content-Type: application/json`
- **请求体**：

  | 字段 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | `username` | string | 是 | 管理员账号名 |
  | `password` | string | 是 | 明文口令，仅用于本次比对，不写入配置、不落库、不记录日志 |

  ```json
  {
    "username": "zhangsan",
    "password": "123456"
  }
  ```

- **响应成功（200 OK）**：

  ```json
  {
    "code": 0,
    "status": "success",
    "data": {
      "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ6aGFuZ3NhbiIsImV4cCI6MTc4OTczNjU1NCwiaWF0IjoxNzg5NjUwMTU0fQ.zS_VjKoJBXefq7VQbtYEffH_i5RKtBFPedD8b-8vwRo"
    }
  }
  ```

- **响应字段说明**：

  | 字段 | 类型 | 说明 |
  |------|------|------|
  | `code` | int | 业务响应码，`0` 表示成功 |
  | `data.token` | string | JWT 令牌，前端需自行保存，后续请求与 WebSocket 连接携带 |

- **错误响应**：

  | 状态码 | 响应体示例 | 触发场景 |
  |--------|------------|----------|
  | `400` | `{"code":400,"status":"error","error":"用户名和密码不能为空"}` | 请求体为空、字段缺失或 JSON 格式非法 |
  | `401` | `{"code":401,"status":"error","error":"用户名或密码错误"}` | 账号不存在或口令错误（不区分二者，避免暴露账号是否存在） |
  | `429` | `{"code":429,"status":"error","error":"请求过于频繁, 请稍后重试"}` | 触发 IP 限流 |
  | `500` | `{"code":500,"status":"error","error":"签发 token 失败"}` | 令牌签发失败（防御性分支） |

- **调用示例**：

  ```bash
  curl -X POST http://localhost:8080/api/auth/login \
    -H "Content-Type: application/json" \
    -d '{"username":"zhangsan","password":"123456"}'
  ```

> 安全说明：口令在服务端以 bcrypt 哈希形式保存，校验通过 `bcrypt.CompareHashAndPassword` 完成，明文口令不写入日志；默认预置账号仅用于本地开发与演示，生产部署应通过环境变量注入真实密钥与哈希。

### 2.2 WebSocket 接入

**接口描述**：客户端携带登录令牌通过 WebSocket 协议连接到网关，建立全双工长连接。连接建立后自动注册到全局连接池，并按 `roomId` 加入对应房间；服务端定期发送 Ping 帧进行心跳保活，并支持向客户端推送下行消息。

- **请求方法**：`GET`
- **请求路径**：`/ws`
- **请求参数**：

  | 参数 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | `clientId` | string | 是 | 客户端唯一标识，须与登录账号匹配（见下方身份绑定），仅允许字母、数字、下划线、短横线 |
  | `roomId` | string | 是 | 房间 ID，标识客户端所属分组，格式要求同 `clientId` |
  | `token` | string | 是 | JWT 令牌，取自登录接口返回的 `data.token`。浏览器的 WebSocket API 无法自定义请求头，因此通过 query 参数传递 |

- **身份绑定**：`clientId` 必须等于令牌中的账号名（`sub` 字段），或以「账号名 + 短横线」为前缀，例如账号为 `zhangsan` 时可用 `zhangsan`、`zhangsan-1`、`zhangsan-tab2`。同一账号需要多开页面时用后缀区分，既能通过重复连接检查，又能防止冒用他人的连接标识。

- **参数格式**：`^[a-zA-Z0-9_-]+$`，长度至少为 1
- **协议升级**：HTTP → WebSocket（状态码 `101 Switching Protocols`）
- **鉴权时机**：令牌校验在协议升级之前完成，校验失败时不会建立 WebSocket 连接，客户端收到 HTTP `401` 响应

**连接成功**：
- 协议升级成功，进入 WebSocket 全双工通信模式
- 客户端自动注册，并加入 `roomId` 对应的房间
- 服务端每 30 秒（可配置）发送一次 Ping 帧；客户端须在 60 秒（可配置）内回复 Pong 帧
- 若 `clientId` 已存在，新连接会被拒绝并收到关闭帧（状态码 4002）

**连接失败 / 被拒绝**：

| 场景 | 客户端收到的结果 | 说明 |
|------|------------------|------|
| 未携带令牌或令牌无效 / 已过期 | 握手阶段 HTTP `401` | 鉴权未通过，连接不会建立 |
| `clientId` 或 `roomId` 缺失 | 关闭码 `4000` | 参数缺失 |
| `clientId` 或 `roomId` 含非法字符 | 关闭码 `4001` | 参数格式无效 |
| `clientId` 已被占用 | 关闭码 `4002` | 重复连接被拒绝 |
| `clientId` 与令牌身份不符 | 关闭码 `4004` | 身份绑定校验失败，防止冒用 |
| 网关正在优雅退出 | 关闭码 `1001` | 服务正在关闭，拒绝新连接 |
| 正常关闭 / 服务优雅关闭现有连接 | 关闭码 `1000` | 正常关闭 |

**协议升级失败（HTTP 错误）**：
- `500 Internal Server Error`：WebSocket 协议升级失败（例如请求头缺少 Upgrade 字段）
  ```json
  {"code":500,"status":"error","error":"WebSocket 协议升级失败"}
  ```

**JavaScript 接入示例**：
```javascript
// token 来自 POST /api/auth/login 返回的 data.token
const ws = new WebSocket(
  "ws://localhost:8080/ws?clientId=zhangsan-1&roomId=room1&token=" + token
);
ws.onopen = () => console.log("连接已建立");
ws.onmessage = (e) => console.log("收到消息:", e.data);
ws.onclose = (e) => console.log("连接已关闭，状态码:", e.code, e.reason);
ws.onerror = () => console.log("连接出错（可能是令牌无效，握手阶段已返回 401）");
```

### 2.3 全服广播

**接口描述**：向当前网关所有在线 WebSocket 客户端广播消息。业务后端通过此接口推送全局通知、系统公告等。

- **请求方法**：`POST`
- **请求路径**：`/api/broadcast`
- **请求头**：`Content-Type: application/json`、`Authorization: Bearer <token>`
- **请求体**：合法的 JSON 对象或 JSON 数组，网关只校验 JSON 合法性，消息内容原样转发
  ```json
  {
    "type": "text",
    "data": "这是一条全服广播消息",
    "timestamp": 1770451200000
  }
  ```

- **响应成功（200 OK）**：
  ```json
  {"code":0,"status":"success","data":null}
  ```

- **错误响应**：

  | 状态码 | 响应体示例 | 触发场景 |
  |--------|------------|----------|
  | `400` | `{"code":400,"status":"error","error":"请求体不能为空"}` | 请求体为空 |
  | `400` | `{"code":400,"status":"error","error":"无效的 JSON 格式"}` | 非 JSON 或纯数字请求体 |
  | `401` | `{"code":401,"status":"error","error":"缺少 token"}` | 未携带令牌；令牌无效或已过期时返回「token 无效或已过期」 |
  | `429` | `{"code":429,"status":"error","error":"请求过于频繁, 请稍后重试"}` | 触发 IP 限流 |

## 三、WebSocket 通信协议

### 3.1 连接生命周期

```
客户端                                       网关
  |                                           |
  |-- POST /api/auth/login ----------------->|
  |<-- 200 {"data":{"token":"..."}} ---------|
  |                                           |
  |-- GET /ws?clientId&roomId&token=xxx ---->|
  |              (校验令牌 + 校验身份绑定)      |
  |<-- 101 Switching Protocols ---------------|
  |                                           |
  |<-- (服务端推送消息) ------------------------|
  |-- (上行消息，仅维持活跃) ------------------>|
  |<-- Ping (默认每30s) -----------------------|
  |-- Pong (默认60s内回复) ------------------->|
  |                                           |
  |-- (连接关闭/心跳超时) --------------------->|
  |<-- 关闭帧 1000 ---------------------------|
  |-- 注销，离开房间 ------------------------->|
  |                                           |
  |-- (服务优雅退出时) ------------------------>|
  |<-- 关闭帧 1000 / 新连接 1001 -------------|
```

### 3.2 消息格式

- **下行消息**（服务端 → 客户端）：服务端以 WebSocket TextMessage 帧推送 UTF-8 编码的 JSON 字符串。网关不解析、不修改消息字段，推送内容为调用方提交的原始请求体。示例：

  ```json
  {
    "type": "text",
    "data": "消息内容",
    "timestamp": 1770451200000
  }
  ```

- **上行消息**（客户端 → 服务端）：当前版本不对上行消息做业务处理，仅通过读取消息维持连接活跃，并累计到 `ws_messages_received_total` 指标。网关不要求上行消息格式。

### 3.3 心跳保活

- 服务端以可配置间隔（默认 30 秒）发送 Ping 帧
- 客户端须在可配置超时时间（默认 60 秒）内回复 Pong 帧
- 每次收到 Pong 后，服务端延长该连接的读超时
- 超时未响应则服务端主动关闭连接，并触发注销流程

| 参数 | 默认值 | 配置项 | 环境变量 |
|------|--------|--------|----------|
| Ping 发送间隔 | 30s | `heartbeat.ping_interval_seconds` | `WS_PING_INTERVAL` |
| Pong 等待超时 | 60s | `heartbeat.pong_wait_seconds` | `WS_PONG_WAIT` |
| Ping 帧写入超时 | 10s | `heartbeat.ping_write_timeout_seconds` | - |
| 读超时 | 60s | `websocket.read_deadline_seconds` | - |
| 写超时 | 10s | `websocket.write_deadline_seconds` | - |
| 控制帧写入超时 | 1s | `websocket.control_write_timeout_seconds` | - |

### 3.4 WebSocket 关闭码

| 关闭码 | 含义 | 触发场景 |
|--------|------|----------|
| `1000` | 正常关闭 | 客户端主动关闭、连接异常断开后的清理、服务优雅关闭现有连接 |
| `1001` | 服务正在关闭 | 优雅退出期间拒绝新连接 |
| `4000` | 参数缺失 | `clientId` 或 `roomId` 为空 |
| `4001` | 参数格式无效 | `clientId` 或 `roomId` 包含非法字符 |
| `4002` | clientId 已存在 | 重复连接被拒绝 |
| `4003` | 鉴权信息缺失 | 请求未经鉴权中间件（防御性分支，正常流程不可达） |
| `4004` | 身份不匹配 | `clientId` 与令牌中的账号不符 |

## 四、鉴权机制

### 4.1 令牌结构与签发

登录成功后返回的令牌是标准 JWT，由三段用 `.` 连接组成：`header.payload.signature`。

| 部分 | 内容 | 说明 |
|------|------|------|
| header | `{"alg":"HS256","typ":"JWT"}` | 声明签名算法与令牌类型，固定不变 |
| payload | `{"sub":"账号名","iat":签发时间,"exp":过期时间}` | 载荷为 Base64URL 编码，**可被解码查看，不得存放敏感信息** |
| signature | 对 `header.payload` 用密钥计算 HMAC-SHA256 的结果 | 密钥（`jwt.secret`）不进入令牌，仅参与签名与验签 |

- 签发算法：`HS256`（HMAC-SHA256）
- 默认有效期：24 小时，由 `jwt.ttl_hours` 或环境变量 `WS_JWT_TTL_HOURS` 配置
- 时间字段以 Unix 秒表示

### 4.2 令牌传递方式

| 场景 | 传递方式 | 示例 |
|------|----------|------|
| HTTP 接口 | 请求头 `Authorization` | `Authorization: Bearer eyJhbGciOi...` |
| WebSocket | query 参数 `token` | `/ws?clientId=zhangsan-1&roomId=room1&token=eyJhbGciOi...` |

> WebSocket 之所以使用 query 参数，是因为浏览器的 WebSocket API 不支持自定义请求头。中间件两种方式都支持，HTTP 接口优先读取请求头。

### 4.3 校验规则

服务端校验依次包含：拆分并解码令牌、比对签名、确认算法为 `HS256`、确认令牌携带 `exp` 且未过期。任一环节失败即返回 401：

```json
{"code":401,"status":"error","error":"token 无效或已过期"}
```

校验通过后，服务端把令牌载荷写入请求上下文，供后续处理函数获取当前操作者身份（如日志记录、WebSocket 身份绑定）。

### 4.4 配置项与环境变量

| 配置项 | 默认值 | 环境变量 | 说明 |
|--------|--------|----------|------|
| `jwt.secret` | `dev-secret-change-me`（仅开发） | `WS_JWT_SECRET` | 签名密钥，长度不少于 16 字符，泄漏即可伪造令牌 |
| `jwt.ttl_hours` | 24 | `WS_JWT_TTL_HOURS` | 令牌有效期（小时） |
| `auth.username` | `zhangsan`（仅开发） | `WS_AUTH_USERNAME` | 预置管理员账号名 |
| `auth.password_hash` | 演示用 bcrypt 哈希 | `WS_AUTH_PASSWORD_HASH` | 口令的 bcrypt 哈希（60 字符），不存明文 |

口令哈希可使用项目内 `cmd/HashGenerate` 工具生成：

```bash
go run cmd/HashGenerate -p "<明文口令>"
```

> 安全建议：仓库内的 `dev-secret-change-me` 与演示账号仅供本地开发，生产部署必须通过环境变量注入真实密钥与哈希；同时应在网关前置反向代理启用 HTTPS，避免令牌在传输过程中被截获。

### 4.5 令牌过期处理

令牌过期后所有受保护接口返回 `401`。前端捕获到 401 时应清除本地保存的令牌并跳转登录页重新获取，无需额外的心跳续期接口。

## 五、错误码说明

### 5.1 HTTP 状态码

| HTTP 状态码 | 业务含义 | 说明 |
|-------------|----------|------|
| `200 OK` | 请求成功 | 正常返回业务数据 |
| `400 Bad Request` | 请求参数错误 | 请求体为空、非 JSON、纯数字等 |
| `401 Unauthorized` | 未通过鉴权 | 未携带令牌、签名无效或令牌已过期 |
| `404 Not Found` | 资源不存在 | 房间不存在或无在线成员、客户端离线或不存在 |
| `429 Too Many Requests` | 触发限流 | 请求频率超过令牌桶阈值 |
| `500 Internal Server Error` | 服务内部错误 | 当前主要用于 WebSocket 协议升级失败等场景 |

### 5.2 业务响应码

| 业务码 | 含义 | 说明 |
|--------|------|------|
| `0` | 成功 | 所有正常响应 |
| `400` | 请求参数错误 | JSON 格式无效、请求体为空等 |
| `401` | 未通过鉴权 | 令牌缺失、签名无效或已过期 |
| `404` | 资源不存在 | 目标房间或目标客户端不存在 |
| `429` | 触发限流 | 请求频率超过令牌桶阈值 |
| `500` | 服务器内部错误 | WebSocket 协议升级失败等 |

### 5.3 限流说明

- 作用范围：`/api` 路由组下的全部 REST 接口
- 算法：基于客户端 IP 的令牌桶（`golang.org/x/time/rate`）
- 默认参数：令牌生成间隔 12 秒，桶容量 5，即同一 IP 连续第 6 次请求返回 429
- 配置方式：`configs/config.toml` 的 `[ratelimit]` 段，或环境变量 `WS_RATELIMIT_INTERVAL`、`WS_BURST`
- 响应格式：触发限流时返回 `{"code":429,"status":"error","error":"请求过于频繁, 请稍后重试"}`，与其他接口使用同一响应信封
- 客户端 IP 取值：网关默认不信任任何反向代理，直接采用 TCP 连接的对端地址，因此客户端自行伪造的 `X-Forwarded-For`、`X-Real-IP` 请求头不会影响限流判定；若在网关前部署反向代理，需先配置可信代理网段才会采信这些头部
