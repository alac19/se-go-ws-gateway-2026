## 一、引言

### 1.1 项目背景
在实时 Web 应用（如直播弹幕、在线客服、金融行情推送、多人协作）中，WebSocket 已成为服务端主动推送数据的标准全双工协议。然而，生产环境直接暴露 WebSocket 服务需解决连接管理、心跳保活、消息路由、优雅关闭等通用问题。  
本项目的目的是**从零构建一个轻量级、高并发的 WebSocket 网关**，作为业务后端与前端长连接之间的统一流量入口，沉淀可复用的实时推送基础设施，并深入理解 Go 语言的并发模型与网络编程实践。

### 1.2 项目目标
- 实现 WebSocket 长连接的接入、注册、注销与心跳保活。
- 提供 REST API 供业务后端调用，支持全服广播、房间广播、单播三种消息推送方式。
- 单机支持 **5,000+并发长连接**，P99 消息推送延迟 **< 50ms**。
- 支持优雅启停（服务关闭时无损断开所有连接）。
- 集成 Prometheus 指标与结构化日志，便于监控和排障。
- 所有关键运行参数（心跳间隔、读写超时、通道缓冲区大小）均可通过配置文件和环境变量动态调整，满足性能调优需求。

### 1.3 适用范围
本文档适用于本项目的需求分析、系统设计、编码实现、测试验证及部署运维阶段，作为全流程开发依据。

### 1.4 用户角色
| 角色 | 职责说明 |
|------|----------|
| **前端客户端** | 通过 WebSocket 协议连接到网关，接收服务端推送的消息，并定时响应 Pong 帧保持连接活跃。 |
| **业务后端** | 通过调用网关提供的 HTTP REST API，触发向客户端推送消息（广播/房间/单播）。 |
| **运维/开发者** | 部署网关服务，通过环境变量调整运行参数，查看 `/metrics` 和日志监控网关健康状态。 |

### 1.5 假定与约束

**假定条件**  
- 客户端均支持 WebSocket 协议（RFC 6455），并能正确处理Ping/Pong 控制帧。  
- 业务后端调用 REST API 时，请求格式符合约定（JSON结构）。  
- 生产环境部署时，网关实例可通过 Nginx 或 SLB 做负载均衡（分布式场景依赖 Redis 扩展）。

**技术约束**  
- 开发语言：Go 1.21+。  
- WebSocket实现：`gorilla/websocket`。  
- HTTP路由框架：允许使用 `gin` 或 `gorilla/mux`，本项目选择 `gin` 以提升团队开发效率。  
- 存储：**不依赖外部数据库**，连接状态与房间成员均存储于内存（`sync.Map` + `RWMutex`）。  
- Redis扩展：可选，仅在需要多实例消息广播时启用 `go-redis/redis`。  
- 配置管理：默认使用 `config.toml`，且**所有关键参数支持环境变量覆盖**，用于部署调优。  
- 本项目暂不实现：用户登录认证、JWT鉴权、消息持久化、分布式一致性保障。

## 二、功能性需求

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| **FR-01** | **连接生命周期管理** <br> 1. 提供 `/ws` 端点，支持 `clientId` 和 `roomId` 查询参数，完成HTTP到WebSocket的协议升级。 <br> 2. 连接建立后，自动将客户端注册到全局连接池（基于 `sync.Map`），并按 `roomId` 维护房间成员列表。 <br> 3. 连接断开（主动关闭、异常掉线、心跳超时）时，自动从连接池和房间列表中注销，释放资源。 <br> 4. 实现Ping/Pong心跳保活：服务端每隔可配置间隔（默认30s）发送Ping帧，客户端须在可配置超时时间（默认60s）内回复Pong，否则服务端主动关闭连接并触发注销。 <br> 5. 实现优雅启停：收到 SIGINT/SIGTERM 信号时，首先停止接收新连接，然后遍历所有在线连接发送WebSocket Close控制帧（状态码1000），等待可配置的宽限期（默认5s）后强制关闭剩余连接，确保所有消息被发送完毕且资源无泄漏。 | 高 |
| **FR-02** | **HTTP管理接口（REST API）** <br> 向外暴露四个管理端点，供业务后端调用以触发消息推送或查询状态： <br> • `POST /api/broadcast` – 向所有在线客户端广播消息。 <br> • `POST /api/room/:roomId/broadcast` – 向指定房间内的所有客户端广播消息（若房间不存在，返回404）。 <br> • `POST /api/client/:clientId/send` – 向指定的单个客户端发送消息（若离线，返回404或状态失败）。 <br> • `GET /api/stats` – 返回当前网关的统计信息，包括总连接数、各房间连接数分布、服务运行时长等。 <br> 所有接口请求体为固定JSON格式：`{"type":"text","data":"消息内容","timestamp":1234567890}`，响应体统一包含 `status`、`code`、`data`/`error` 字段。 | 高 |
| **FR-03** | **消息路由与分发** <br> 实现三种推送模式的内核分发逻辑，供FR-02的REST接口调用： <br> 1. **全服广播**：遍历全局连接池，向所有在线客户端的Send通道发送消息。 <br> 2. **房间广播**：根据 `roomId` 获取房间成员列表，仅向该房间内的客户端发送消息。 <br> 3. **单播**：根据 `clientId` 直接定位目标Client，向对应Send通道发送消息。 <br> 为防止单个慢客户端阻塞整个广播过程，发送时需采用 `select` 的 `default` 分支进行**非阻塞尝试**，或为每条发送启动独立goroutine（在实现中需明确选择一种策略，并保证资源可控）。 | 高 |
| **FR-04** | **Redis Pub/Sub 扩展（可选）** <br> 支持通过环境变量启用Redis模式（`REDIS_URL` 非空时激活）。启用后，每个网关实例订阅指定Redis频道，当收到跨实例的广播消息时，将其转发到本实例的本地连接池。此功能用于水平多实例部署时的消息同步，但**本版本不强制实现**，作为架构上的可拔插扩展点。 | 低 |

## 三、非功能性需求

| 编号 | 需求描述 | 指标 / 约束 |
|------|----------|-------------|
| **NFR-01** | **性能** <br> • 单机支持并发WebSocket长连接数不少于5,000。 <br> • 消息推送延迟：在5,000连接同时在线时，广播消息的P99延迟 < 50ms。 <br> • HTTP管理接口（如 `/api/stats`）响应时间 < 100ms（连接数较大时）。 <br> • 单个连接的内存开销须控制在合理范围内（例如 ≤ 10KB），避免内存泄漏。 | 使用 `wscat`、`hey` 或自定义Python脚本进行压测验证。 |
| **NFR-02** | **可靠性与稳定性** <br> • 连接意外断开（如网络闪断）时，`readPump` 必须及时捕获错误并触发清理，不允许出现“僵尸连接”堆积。 <br> • 向客户端Send通道发送消息时，若通道已满（缓冲区为可配置值，默认256），须有丢弃或重试策略，确保不会阻塞其他连接的操作。 <br> • 服务内部panic（如空指针）应被recover捕获，单个连接的异常不得导致整个网关进程崩溃。 <br> • 优雅退出时，保证所有已接收到的数据帧被处理完毕，不会丢失已进入Send通道的数据。 | 运行时监控无内存持续增长；压测过程中不出现进程退出。 |
| **NFR-03** | **可维护性与可观测性** <br> • 集成Prometheus客户端库，暴露 `/metrics` 端点，提供以下指标： <br> &nbsp;&nbsp;- `ws_active_connections`（Gauge）：当前在线连接数。 <br> &nbsp;&nbsp;- `ws_messages_sent_total`（Counter）：累计发送消息总数，按推送类型（广播/房间/单播）打标签。 <br> &nbsp;&nbsp;- `ws_connection_events_total`（Counter）：连接建立/关闭事件计数。 <br> • 使用Go标准库 `slog` 输出结构化日志（JSON格式），记录连接建立、关闭、消息推送失败、心跳超时等关键事件，并包含 `clientId`、`roomId`、耗时等字段。 <br> • 提供健康检查端点（如 `GET /health`），返回200状态码表示服务存活。 | Prometheus指标需在压测报告中呈现；日志级别可通过环境变量动态调整。 |
| **NFR-04** | **安全性** <br> • 在HTTP管理接口层实现**限流防护**：基于IP或全局令牌桶，限制高频请求（如每秒最大请求数可配置），防止恶意调用压垮网关。 <br> • 对REST API的请求体进行严格的JSON Schema校验（如字段类型、必填项），拒绝非法格式。 <br> • WebSocket升级时，检查 `clientId` 是否为空或含特殊字符，避免注入式攻击（当前版本不采用JWT，但需做好基本参数校验）。 <br> • 生产环境中可通过环境变量决定是否启用TLS（WSS），证书由外部提供。 | 限流算法采用令牌桶（`golang.org/x/time/rate`），阈值默认100 req/s。 |
| **NFR-05** | **可移植性** <br> • 提供 `Dockerfile` 和 `docker-compose.yml`，支持一键启动网关服务（含可选Redis依赖）。 <br> • 最终镜像大小不超过50MB（使用Alpine基础镜像）。 <br> • 所有配置项通过 `config.toml` 集中管理，且支持环境变量覆盖（如 `WS_PING_INTERVAL`），便于在Kubernetes等容器编排平台中动态调整。 | 在干净的Ubuntu 24.04环境中验证容器化部署流程。 |
