## 一、维护概述

本手册为 WebSocket 网关的日常维护提供操作指导，涵盖服务管理、日志查看、配置修改、常见问题处理等场景。

| 项目 | 说明 |
|------|------|
| 系统名称 | Go 轻量级 WebSocket 网关 |
| 技术栈 | Go 1.26.4 + Gin + gorilla/websocket |
| 部署方式 | Docker Compose 容器化部署 |
| 主要端口 | 8080（业务）、6060（pprof）、9090（Prometheus） |
| 配置文件 | `configs/config.toml` |

## 二、日常维护操作

### 2.1 服务管理

| 操作 | 命令 |
|------|------|
| 本地启动 | `go run cmd/gateway/main.go` |
| 容器启动 | `docker-compose up -d` |
| 容器停止 | `docker-compose down` |
| 重启容器 | `docker-compose restart gateway` |
| 查看状态 | `docker-compose ps` |
| 优雅退出 | `docker kill --signal=SIGTERM ws-gateway` |

### 2.2 日志查看

```bash
# 容器日志
docker-compose logs -f gateway

# 本地日志（JSON 格式）
tail -f logs/gateway.log

# 过滤错误日志
grep '"level":"ERROR"' logs/gateway.log
```

### 2.3 配置修改

1. 编辑 `configs/config.toml` 文件
2. 重启服务使配置生效（不支持热加载）：
   ```bash
   docker-compose restart gateway
   ```

| 常用配置项 | 说明 |
|------------|------|
| `port` | 监听端口 |
| `log.level` | 日志级别（debug/info/warn/error） |
| `ping_interval_seconds` | Ping 间隔 |
| `pong_wait_seconds` | Pong 超时 |
| `timeout_seconds` | 优雅退出宽限期 |

## 三、常见问题与解决方案

### 3.1 服务启动失败

| 问题 | 解决方案 |
|------|----------|
| 配置文件格式错误 | `cat configs/config.toml` 检查语法 |
| 端口被占用 | `netstat -tlnp | grep 8080` 检查 |
| 日志目录无权限 | `mkdir -p logs` |
| 容器启动失败 | `docker-compose logs gateway` 查看日志 |

### 3.2 连接问题

| 现象 | 解决方案 |
|------|----------|
| 状态码 4000 | URL 缺少 `clientId` 或 `roomId` 参数 |
| 状态码 4001 | 参数含非法字符，仅允许 `a-zA-Z0-9_-` |
| 状态码 4002 | `clientId` 已被占用，使用唯一 ID |
| 连接自动断开 | 检查客户端是否响应 Pong 帧 |
| 返回 429 | 触发限流，等待令牌恢复或调整限流配置 |

### 3.3 性能问题

| 问题 | 解决方案 |
|------|----------|
| 高并发延迟高 | 日志级别改为 `error`，减少 I/O |
| 高并发延迟高 | 检查限流配置（`ratelimit`） |
| 内存持续增长 | 采集 pprof heap 分析（见 3.4） |

### 3.4 pprof 性能分析

```bash
# CPU Profile（30 秒采样）
go tool pprof -http=:8081 http://localhost:6060/debug/pprof/profile?seconds=30

# Heap Profile
go tool pprof -http=:8081 http://localhost:6060/debug/pprof/heap
```

## 五、快速故障处理

| 故障场景 | 处理步骤 |
|----------|----------|
| 容器崩溃 | 1. `docker-compose logs gateway --tail=50` 查看错误<br>2. 配置错误则修改后重启<br>3. 代码缺陷则回滚到旧版本 |
| 连接数异常突增 | 1. 查看 `/api/stats`<br>2. 检查是否有攻击流量<br>3. 临时调整限流配置 |
| 内存持续增长 | 1. 采集 pprof heap 分析<br>2. 必要时重启服务 |
