## 三、代码规范

### 3.1 命名规范

| 类型 | 规则 | 示例 |
|------|------|------|
| 包名 | 小写、单数、无下划线 | `handler`, `service`, `model` |
| 结构体 | 大驼峰（导出） | `ClientManager`, `MessageRouter` |
| 接口 | 大驼峰，单方法可加 `-er` | `Limiter` |
| 函数/方法 | 大驼峰（导出）或小驼峰（私有） | `SendBroadcast`, `waitForClients` |
| 变量 | 大驼峰（导出）或小驼峰（私有） | `clientID`, `lastPong`, `SendChan` |
| 常量 | 大驼峰 | `CloseCodeMissingParam`, `BizCodeSuccess` |
| 文件名 | 小写，下划线分隔 | `client_manager.go`, `ws_handler_test.go` |
| 缩写词 | 导出时全大写（URL、HTTP、API、IP、ID）；私有时全小写 | `ClientID`, `RoomID`；`clientID`, `roomID` |

### 3.2 注释规范

- **包注释**：每个包必须有一个包级注释，写在 `package` 声明上方，说明该包的职责。包注释使用英文。
- **导出符号注释**：所有导出的类型、函数、常量必须有文档注释，以符号名开头，使用中文描述功能。
- **复杂逻辑注释**：对于复杂的业务逻辑（如非阻塞发送策略、优雅退出流程），须添加行内注释说明设计意图。

**示例**：

```go
// ClientManager 连接管理器，采用 CSP（Communicating Sequential Processes）模型，
// 通过 channel 进行协程间通信，使用 sync.Map 保证并发安全。
// 负责客户端的注册、注销、查询和优雅关闭。
type ClientManager struct {
    clients      sync.Map           // 存储所有在线客户端，key: clientID, value: *model.Client
    register     chan *model.Client // 注册通道
    unregister   chan string        // 注销通道
}
```

### 3.3 错误处理规范

- 使用 `fmt.Errorf` 或 `errors.New` 创建错误。
- 在 `service` 层通过返回值传递错误，由 `handler` 层处理。
- 在 `handler` 层根据业务结果设置对应的 HTTP 状态码（200、400、404、500）。
- 禁止忽略错误（`_` 接收），必须显式处理或向上传递。
- 使用 `slog.Error` 记录错误日志，包含 `error` 字段。

### 3.4 代码风格

- 使用 `go fmt` 自动格式化所有代码。
- 使用 `go vet` 检查潜在的代码问题。
- 使用 `go mod tidy` 保持 `go.mod` 和 `go.sum` 的整洁。
- 每行长度建议不超过 120 字符。
- 导出函数按逻辑分组，使用空行分隔。
- 禁止在业务代码中使用 `panic`（仅在初始化失败时使用，如配置加载失败）。
- 所有 `goroutine` 的启动必须明确其退出条件（通过 `context` 或显式关闭信号）。

## 四、配置规范

### 4.1 配置文件格式

使用 TOML 格式，最终版 `configs/config.toml`：

```toml
[server]
port = 8080

[websocket]
read_buffer_size = 1024
write_buffer_size = 1024
read_deadline_seconds = 60
write_deadline_seconds = 10
control_write_timeout_seconds = 1

[heartbeat]
ping_interval_seconds = 30
pong_wait_seconds = 60
ping_write_timeout_seconds = 10

[channel]
send_buffer_size = 256
register_buffer_size = 256
unregister_buffer_size = 256

[ratelimit]
every_seconds = 12
burst = 5

[graceful_shutdown]
timeout_seconds = 5

[log]
level = "error"
file_path = "logs/gateway.log"
```

### 4.2 配置加载流程

1. 默认加载 `configs/config.toml`。
2. 支持通过环境变量覆盖关键参数。
3. 加载完成后执行校验（如端口范围 1-65535、超时值正数、PongWait > PingInterval 等），校验失败则启动失败。

### 4.3 环境变量覆盖规则

环境变量以 `WS_` 为前缀：

| 环境变量 | 说明 | 默认值 |
|----------|------|--------|
| `WS_PORT` | 服务监听端口 | 8080 |
| `WS_PING_INTERVAL` | Ping 帧发送间隔（秒） | 30 |
| `WS_PONG_WAIT` | Pong 响应超时（秒） | 60 |
| `WS_RATELIMIT_INTERVAL` | 限流令牌生成间隔（秒） | 12 |
| `WS_BURST` | 限流桶容量 | 5 |
| `WS_SHUTDOWN_TIMEOUT` | 优雅退出宽限期（秒） | 5 |

> **注意**：日志级别和 Gin 运行模式推荐在配置文件或代码中设置，环境变量覆盖优先级高于配置文件。

## 五、日志规范

- **日志库**：使用 Go 标准库 `log/slog`。
- **输出格式**：JSON 格式，便于日志采集和检索。
- **日志级别**：支持 `debug`、`info`、`warn`、`error` 四个级别，通过配置文件控制。
- **日志级别建议**：开发环境使用 `info`，生产环境使用 `error`。
- **结构化字段**：关键事件必须包含结构化字段：

| 事件 | 字段 |
|------|------|
| 连接建立 | `clientId`, `roomId` |
| 连接关闭 | `clientId`, `roomId`, `error` |
| 消息推送失败 | `clientId`, `error` |
| 心跳超时 | `clientId`, `error` |
| 优雅退出 | 无 |

**示例日志行**：

```json
{"time":"2026-08-09T10:00:00Z","level":"ERROR","msg":"readPump 读取失败","clientId":"test","error":"websocket: close 1000"}
```

**日志轮转**（Docker 环境）：
```yaml
logging:
  driver: "json-file"
  options:
    max-size: "10m"
    max-file: "3"
```

### 7.2 Docker 镜像

- 使用多阶段构建，最终镜像基于 Alpine。
- 镜像大小 34.9MB。
- 暴露 8080（业务）和 6060（pprof）端口。
- 健康检查：`HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 CMD wget --spider http://localhost:8080/health || exit 1`

**Dockerfile**：

```dockerfile
# 第一阶段：编译
FROM golang:1.26.4-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go env -w GOPROXY=https://goproxy.cn,direct && go env -w GOSUMDB=sum.golang.google.cn
RUN go mod download
COPY . ./
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o gateway ./cmd/gateway

# 第二阶段：运行
FROM alpine:latest
RUN apk add --no-cache ca-certificates
WORKDIR /app
COPY --from=builder /app/gateway ./
COPY ./configs/config.toml ./configs/
RUN mkdir -p ./logs
EXPOSE 8080 6060
HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1
CMD ["./gateway"]
```

## 八、版本控制规范

### 8.1 分支策略

| 分支 | 说明 | 合并来源 |
|------|------|----------|
| `main` | 稳定生产版本，受保护分支 | 仅接受来自 `develop` 的 PR |
| `develop` | 开发集成分支 | 所有 `feature/*` 分支 |
| `feature/*` | 功能开发分支 | 从 `develop` 拉出，完成后 PR 回 `develop` |
| `hotfix/*` | 紧急修复分支 | 从 `main` 拉出，完成后 PR 回 `main` 和 `develop` |

### 8.2 提交信息规范

格式：

```
<type>: <subject>

[optional body]
```

**Type 类型**：

| 类型 | 说明 |
|------|------|
| `feat` | 新增功能 |
| `fix` | 修复 Bug |
| `docs` | 文档更新 |
| `refactor` | 代码重构（不改变行为） |
| `test` | 测试相关 |
| `chore` | 构建/工具变动 |

**示例**：

```
feat: 实现 WebSocket 连接升级与注册逻辑
fix: 修复优雅退出时连接未正确关闭的问题
docs: 补充系统设计文档第 4 章数据流设计
chore: 完善代码注释与格式
```
