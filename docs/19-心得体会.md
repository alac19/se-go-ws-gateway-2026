# **Go轻量级WebSocket网关 – 心得体会**

---

> **项目名称**：se-go-ws-gateway-2026
>
> **日期**：2026-08-09
>
> **编写人**：项目组

---

## 一、整体感受

本次软件工程项目进阶实践，我们小组三人（刘灿阳、罗培友、占鹏辉）共同完成了 Go 轻量级 WebSocket 网关的设计、开发、测试与部署工作。从最初的需求分析到最终的部署交付，我们完整经历了一个软件工程项目的全生命周期。

## 二、技术收获

通过本次实训，我们对 Go 语言的并发模型有了更深入的理解——使用 `sync.Map` 管理连接池、通过 `channel` 实现 CSP 通信模型、利用 `select + default` 实现非阻塞消息发送。在性能调优阶段，我们学会了使用 pprof 火焰图定位瓶颈，发现并移除了 Gin 默认日志中间件，使系统在 Windows 环境下达到 50,000+ QPS。此外，我们还掌握了 Docker 多阶段构建、健康检查、日志轮转、回滚验证等容器化部署的最佳实践。

## 三、工程化认知

我们深刻体会到“文档先行”的价值——先编写需求规格说明书和系统设计文档，再开始编码，这种方式有效减少了后期返工成本。通过 Git 分支策略（`main` / `develop` / `feature/*`）和 PR 代码审查流程，我们保证了代码质量与协作效率。单元测试、集成测试、性能测试和用户验收测试相结合的三层测试体系，让我们对系统质量有了充分的信心。

## 四、团队协作

模块化分工让我们能够并行开发，互不阻塞。虽然期间遇到了 Git merge 冲突、全局单例导致的测试污染、优雅退出期间的竞态条件等问题，但通过及时沟通和 Code Review，这些问题都得到了妥善解决。

## 五、不足与展望

我们的性能测试主要集中在单机上，对分布式场景考虑不足，部分文档由一人主笔，时间分配也有待优化。未来我们将深入学习 Linux 网络编程、Redis 分布式同步和 Kubernetes 容器编排，为系统的水平扩展和高可用部署做好准备。

## 六、结语

感谢指导老师秦勇老师在选题和组会中的指导与帮助。通过本次实训，我们对软件工程的完整流程有了更深刻的认识——它不仅考验编码能力，更考验需求分析、系统设计、团队协作和质量保障的综合能力。
